# 운동 알람 (FitAlarm)

알람이 울리면 **카메라로 내 동작을 인식해서, 정해 둔 맨몸 운동 루틴을 목표 횟수만큼 해야 꺼지는** 안드로이드 알람 앱입니다.
일반 알람 앱의 기본 기능도 모두 들어 있습니다.

- 언어/플랫폼: Kotlin, Android 8.0 (API 26) 이상, targetSdk 35
- 외부 라이브러리: Google ML Kit 포즈 인식 하나 (모델이 APK에 포함되어 **오프라인 동작**, 영상이 외부로 전송되지 않음)
- 화면·카메라·알람은 전부 안드로이드 기본 프레임워크 API로 작성 (Compose/AndroidX 의존 없음)

---

## 1. 빌드하고 폰에 설치하기

1. **Android Studio** 설치 (최신 버전이면 됩니다).
2. 압축을 풀고 Android Studio에서 **File → Open → `FitAlarm` 폴더** 선택.
3. 처음 열면 Gradle Sync가 자동으로 의존성을 내려받습니다 (인터넷 필요, 수 분 소요).
   - "AGP 업그레이드" 안내가 뜨면 그대로 두거나 업그레이드 도우미를 써도 됩니다.
   - Gradle JDK는 Android Studio 내장 JDK(17 이상)를 사용하세요.
4. 폰에서 **설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호 7번 탭** → 개발자 옵션 → **USB 디버깅** 켜기.
5. 폰을 USB로 연결하고 상단의 ▶ **Run 'app'** 클릭.

명령줄로 빌드하려면:

```bash
./gradlew assembleDebug        # app/build/outputs/apk/debug/app-debug.apk 생성
./gradlew test                 # 알람 계산·운동 인식 단위 테스트 실행
```

### Google Play 출시용 파일 (AAB)

- 앱은 Android 16(API 36)을 타깃합니다 (Google Play 요건: 2026-08-31 부터 신규 앱·업데이트는 API 36 이상).
- GitHub Actions 가 빌드할 때마다 **테스트용 APK**(Releases)와 **Play 스토어 업로드용 AAB**(실행 페이지 Artifacts → `FitAlarm-playstore-aab`)를 만듭니다.
- AAB 는 저장소 Secrets 에 등록한 **업로드 키**로 서명됩니다. 등록할 값 4개:
  `UPLOAD_KEYSTORE_BASE64`, `UPLOAD_STORE_PASSWORD`, `UPLOAD_KEY_ALIAS`, `UPLOAD_KEY_PASSWORD`
  (Settings → Secrets and variables → Actions → New repository secret). 키 파일은 저장소에 절대 올리지 마세요.
- Secrets 가 없으면 AAB 는 테스트 키로 시험 빌드만 하고 올리지 않습니다.
- 출시 빌드(release)와 테스트 빌드(debug)는 서명 키가 달라서, 테스트용 APK 를 설치한 폰에 Play 스토어 버전을 깔려면 테스트 앱을 먼저 지워야 합니다.
- 개인정보처리방침: `docs/privacy-policy.md`, Play Console 데이터 보안 양식 답안: `docs/play-console/data-safety.md`

## 3. 기능

### 기본 알람 기능
- 알람 시간 (오전/오후 또는 24시간, 시스템 설정 따라감)
- 반복 요일 (요일별 선택 + 매일/주중/주말/반복 안 함 빠른 선택), 반복 안 하면 1회 울린 뒤 자동으로 꺼짐
- 알람 이름
- 알람음: 기본 알람음 / 시스템 알람음 목록 / **내 음악 파일** / 무음(진동만), 미리 듣기
- 볼륨 (알람 볼륨을 울리는 동안만 설정값으로 바꾸고 끝나면 원래대로 복구), **점점 크게** (30초)
- 진동 켜기/끄기 + 패턴 4종 (기본, 짧게 반복, 길게, 심장 박동)
- **다시 알림**: 반복 주기(1·3·5·10·15·20·30분), 반복 횟수(1·2·3·5·10회·무제한)
- **울림 지속 시간**: 이 시간 안에 안 끄면 자동 다시 알림, 남은 횟수가 없으면 종료 후 "놓친 알람" 알림
- 잠금 화면 위 알람 화면, 상태바 알람 아이콘, 재부팅·시간대 변경 후 자동 재등록
- 목록에서 스위치로 켜고 끄기, 길게 눌러 삭제, "다음 알람까지 n시간 n분" 표시

### 운동 미션
- 7가지 맨몸 운동 중 **여러 개를 골라 루틴**으로 구성 (고른 순서대로 진행), 운동별 횟수 1~200회
  - 스쿼트, 팔굽혀펴기, 점핑잭, 런지, 윗몸일으키기, 제자리 무릎 올리기, 만세(팔 들어올리기)
- 알람이 울리면 "운동 미션 시작" → 전면 카메라 화면에 내 골격이 그려지고 횟수가 올라감
- 미션 중에는 알람 소리가 25%로 줄고 진동이 멈춤. **45초 동안 진행이 없으면 다시 원래 크기로** 울림
- 미션 알람은 알림창이나 뒤로 가기로 끌 수 없음 (다시 알림은 설정에 따라 가능)
- 카메라를 쓸 수 없는 상황(권한 거부, 카메라 고장 등)에서는 갇히지 않도록 **"3초간 누르고 있으면 끄기"** 대비 버튼이 나타남
- 메인 화면 **"운동 연습"** 또는 편집 화면 **"이 루틴 미리 연습하기"**로 알람 없이 인식 테스트 가능

#### 휴대폰 놓는 법
| 운동 | 위치 |
|---|---|
| 스쿼트, 점핑잭, 무릎 올리기 | 정면, 전신이 보이게 약 2m |
| 팔굽혀펴기, 윗몸일으키기, 런지 | **옆쪽**에 세워 두고 측면에서 전신이 보이게 |
| 만세 | 상반신만 보여도 됨 (책상 앞에서 테스트하기 좋음) |

### 2.0 에서 추가된 기능
- **공휴일·휴무일 건너뛰기** (반복 알람마다 켜고 끔)
  - 앱 내장 규칙: 양력 공휴일, 설·추석·부처님오신날(2025~2031 월력요항 날짜표), 노동절·제헌절, 대체공휴일 규칙.
    2027·2028년 공식 월력요항과 일치하는지 테스트로 확인합니다.
  - 구글 공개 공휴일 달력에서 하루 한 번 자동 업데이트 (임시공휴일·선거일 반영, 인터넷 사용)
  - 폰 기본 달력의 공휴일 달력 읽기 (캘린더 권한, 공휴일 달력만 읽음)
  - 내 휴무일(연차·회사 휴무) 직접 등록: 설정 → 쉬는 날
- **오늘의 운동 음성 안내**: 알람이 울리면 소리를 20%로 줄이고 날짜·시각·오늘의 운동을 읽어줌.
  다시 알림으로 울릴 때마다 안내, "1분마다 다시 안내"는 설정에서 켜기. 목소리 2종(밝고 다정한 여성 / 낮고 차분한 남성).
- **운동 중 음성 카운트**: "열하나, 열둘, 세 개 남았어요"
- **보너스 운동 팝업**: 알람 미션을 끝내면 한 번만 제안. 알람 루틴과 다른 부위에서 무작위, 알람 운동 강도에 맞춘 횟수.
  끝까지 하면 다음 제안 +5%(최대 +20%), 중간에 그만두면 한 단계 낮춤. "오늘은 괜찮아요"·바깥 터치·15초 뒤 자동으로 닫힘.
- **개인 보정**: 동작할 때마다 내가 실제로 도달하는 범위를 학습해 판정 기준을 맞춤. 최소 기준선 아래로는 절대 느슨해지지 않음.
- **기록**: 연속 성공 일수(공휴일·알람 없는 날은 끊기지 않음), 월간 달력, 운동량, 보너스 세트
- **홈 화면 위젯**, **백업/복원**, 시스템 라이트/다크 모드에 맞춘 밝은 UI

## 4. 동작 인식 원리 (튜닝하고 싶을 때)

`app/src/main/java/com/fitalarm/app/core/RepCounters.kt`

```
카메라 프레임 → ML Kit 포즈(33개 관절) → 측정값(각도·비율) → EMA 평활화
   → 두 임계값으로 REST / ACTIVE / BETWEEN 판정 (히스테리시스)
   → 상태머신 WAITING_START → REST → ACTIVE → REST … 에서 1회 완성 시 카운트
```

- **시작 자세(REST)를 먼저 확인한 뒤부터 센다**: 화면에 들어오다가 잘못 세는 것 방지
- **두 임계값 사이(BETWEEN)에서는 상태 유지**: 동작 끝에서 몸이 흔들려도 중복 카운트 안 함
- **최소 간격 350ms**: 인식 튐으로 인한 연속 카운트 방지
- 관절 신뢰도 0.5 미만은 무시하고 "조금 뒤로 물러나세요" 같은 안내 표시

인식이 너무 빡빡하거나 느슨하면 `Calibration.kt`의 `CalibrationSpecs`(기본 기준·최소 기준선) 숫자를 바꾸면 됩니다. 예:

| 상수 | 의미 | 기본값 |
|---|---|---|
| `SQUAT_DEPTH` | 스쿼트: 엉덩이 하강 비율 (0 = 무릎 높이). 기본 0.45, 최소 기준선 0.55 | 0.45 / 0.55 |
| `PUSH_UP_ELBOW` | 팔굽혀펴기: 팔꿈치 각도. 기본 100°, 최소 기준선 115° | 100 / 115 |
| `JJ_LEG` | 점핑잭: 발 간격 / 어깨 폭. 기본 1.4, 최소 기준선 1.25 | 1.4 / 1.25 |
| `HIGH_KNEE` | 무릎 올리기: 무릎 높이 비율. 기본 0.35, 최소 기준선 0.45 | 0.35 / 0.45 |

`app/src/test/java/.../RepCounterTest.kt`에 합성 관절 데이터로 만든 테스트가 있으니, 값을 바꾼 뒤 `./gradlew test`로 회귀 확인을 하세요.

## 6. 이 코드가 어디까지 검증되었나

작성 환경에서 Google Maven 접근이 막혀 있어 APK를 직접 빌드하지는 못했고, 대신 다음을 확인했습니다.

- `core` 로직 **단위 테스트 56개 통과** (2.0: 공휴일·대체공휴일 공식 목록 대조, 개인 보정, 보너스, 기록, 음성 문장 추가): 다음 알람 시각(요일/1회성/서머타임), 남은 시간 표시, 7가지 운동의 횟수 인식, 얕은 동작 무시, 흔들림 중복 방지, 서서 하는 꼼수 거부, 루틴 단계 전환
- 앱 전체 Kotlin 코드를 **Android API 35 `android.jar`에 대해 컴파일 성공** (경고 0개, ML Kit은 실제와 같은 시그니처의 스텁 사용)
- **API 28 `android.jar`로도 컴파일**해서, 그 이후에 추가된 API가 모두 `Build.VERSION.SDK_INT` 분기 안에서만 쓰이는지 확인 (lint의 NewApi 검사 대체)
- 리소스 XML 구문, 매니페스트의 클래스·리소스 참조 확인

실제 기기에서 처음 확인해 보면 좋은 것:
1. 1분 뒤 알람을 만들고 화면을 끈 채 기다려 잠금 화면 위로 알람이 뜨는지
2. "운동 연습"으로 각 운동의 인식이 잘 되는지 (조명, 거리)
3. 다시 알림 1분 + 횟수 2회로 설정해 자동 다시 알림 동작 확인
