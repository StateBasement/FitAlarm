# 알람핏(Alarm Fit) 보안 조치 기록

이 문서는 앱을 만들고 배포하면서 취한 보안·개인정보 보호 조치를 기록합니다.
문제가 생겼을 때 "합리적인 보호 조치를 했다"는 근거가 되므로, 구조나 조치가 바뀔 때마다 아래 **변경 기록**에 날짜와 함께 남기세요.

- 작성: Dev_light (kwangge95@gmail.com)
- 기준 버전: 2.4.0 (2026-10-29)

## 1. 구조 요약 (위험을 줄이는 설계)

| 항목 | 내용 | 효과 |
|---|---|---|
| 서버 | 운영하지 않음 | 해킹으로 사용자 데이터가 한꺼번에 유출될 저장소가 없음 |
| 회원가입·로그인 | 없음 | 비밀번호·계정 정보를 보관하지 않음 |
| 개발자가 받는 사용자 데이터 | 없음 (AdMob 보고서는 노출·클릭 수 같은 집계 수치뿐) | 개인정보 유출 사고의 대상 데이터가 없음 |
| 카메라 영상 | 메모리에서 관절 좌표만 계산 후 즉시 폐기, 저장·전송 없음 | 영상 유출 가능성 없음 |
| 앱 데이터 | 앱 전용 내부 저장소 (다른 앱 접근 불가) | 안드로이드 앱 격리로 보호 |

## 2. 데이터 저장·전송

| 데이터 | 위치 | 보호 조치 |
|---|---|---|
| 알람·설정·휴무일·기록·보정 값 | 앱 내부 저장소 | 앱 격리. **구글 클라우드 백업에서 제외** (`data_extraction_rules.xml`, `backup_rules.xml`), 사용자가 새 폰으로 직접 옮길 때만 이전 |
| 백업 파일 | 사용자가 고른 위치 | 내보내기 전 "암호화되지 않음, 공유 금지" 확인 대화상자 |
| 공휴일 목록 요청 | Google 캘린더 공개 달력 | HTTPS, 개인정보 미포함 |
| ML Kit 진단 정보 | Google | HTTPS (Google 관리), 개인정보처리방침에 고지 |
| 광고 요청 (광고 ID, IP, 앱·광고 이용 정보, 진단) | Google AdMob | TLS (Google 관리), 개인정보처리방침 4-2·5항(행태정보)과 데이터 보안 양식에 고지. 운동 기록·카메라·달력·알람 정보는 광고 요청에 넣지 않음 |

- 모든 통신은 HTTPS 로만 허용, 평문 HTTP 차단 (`network_security_config.xml`, `usesCleartextTraffic=false`)
- 광고 SDK 는 앱의 기본 화면(MainActivity)에서만 시작. 잠금 화면 위의 알람·미션 화면에서는 광고 SDK 를 쓰지 않음
- 유럽 등 동의가 필요한 지역은 Google 동의 도구(UMP)로 동의를 받음
- 분석 SDK 없음. 후원(결제) 기능은 꺼져 있음 (`docs/monetization.md`)

## 3. 권한 최소화

| 권한 | 사용처 | 비고 |
|---|---|---|
| 카메라 | 운동 미션 | 미션을 쓸 때만 요청, 거부해도 알람 동작 |
| 캘린더 읽기 | 공휴일 달력 확인 | 선택. 이름에 공휴일·holiday 가 들어간 달력만 조회, 개인 일정 미조회 |
| 알림·정확한 알람·전체 화면 알림·포그라운드 서비스·진동·부팅 완료 | 알람 핵심 기능 | |
| 인터넷·네트워크 상태 | 공휴일 업데이트, 광고, ML Kit | |
| 광고 ID (`AD_ID`) | 광고 표시·측정 | 사용자가 휴대폰 설정에서 삭제하면 전달되지 않음 |
| 기본 전화 상태 (`READ_BASIC_PHONE_STATE`) | 광고 SDK 가 자동 추가 | 일반(설치 시 자동) 권한, 통신망 종류 등만. 전화번호·통화 기록 접근 불가 |

위치, 연락처, 저장소 전체 접근, 마이크 권한은 요청하지 않습니다. 알람음 파일은 시스템 파일 선택기로 사용자가 고른 파일 하나에만 접근합니다.

## 4. 앱 구성 요소 노출

| 구성 요소 | 외부 노출 | 이유·보호 |
|---|---|---|
| MainActivity | 노출 (런처) | 앱 아이콘으로 열기 위해 필요 |
| SystemEventReceiver | 노출 | 부팅·시간 변경 등 **시스템만 보낼 수 있는 보호된 브로드캐스트**만 처리, 그 외 동작은 무시 |
| 그 밖의 화면·서비스·리시버·위젯 | 비노출 (`exported=false`) | 다른 앱이 호출 불가 |
| 광고 SDK 화면(`AdActivity`), ML Kit·Google 공통 구성 요소 | 비노출 | 라이브러리가 추가, 다른 앱이 호출 불가 |
| WorkManager `SystemJobService` (광고 SDK 의존 라이브러리) | 노출 | `BIND_JOB_SERVICE` 권한 필요 → 시스템만 호출 가능 |
| WorkManager `DiagnosticsReceiver` | 노출 | `DUMP` 권한 필요 → 시스템·개발자 도구(adb)만 호출 가능 |

- 빌드된 매니페스트(2.4.0 QA APK)에서 직접 확인함. 라이브러리를 추가·업데이트하면 다시 확인

- 모든 PendingIntent 는 `FLAG_IMMUTABLE` + 명시적 Intent (다른 앱이 내용 변경 불가)
- 출시 빌드는 디버깅 불가(`debuggable=false`)

## 5. 출시 빌드·서명·배포

- 출시 빌드는 R8 로 코드 축소·난독화 (`isMinifyEnabled`, `isShrinkResources`). 출시와 같은 설정의 QA 빌드로 실기기 확인
- **Play 앱 서명** 사용: 사용자에게 배포되는 앱 서명 키는 Google 이 보관
- **업로드 키**: GitHub 저장소 Secrets 에만 보관, 저장소에 파일 없음(`.gitignore` 로 차단), 개발자가 별도 오프라인 백업
- 업로드 키가 유출돼도 Play Console 계정 없이는 배포 불가, Play Console 에서 업로드 키 재설정 가능
- GitHub Actions: `main` 브랜치 push·수동 실행에서만 동작, 포크에서 온 PR 에는 Secrets 가 전달되지 않음
- 출시용 AAB 는 공개 Releases 가 아닌 빌드 Artifacts 에만 30일 보관
- 저장소의 `fitalarm-debug.keystore` 는 테스트용(공개돼도 Play 배포와 무관)

## 7. 사고 대응 절차

**개발자 계정 탈취가 의심될 때**
1. Google·GitHub 비밀번호 즉시 변경, 다른 기기 로그아웃, 2단계 인증 재설정
2. Play Console 에서 최근 출시·변경 내역 확인, 모르는 출시가 있으면 중지(출시 일시중지)
3. 업로드 키 유출이 의심되면 Play Console 에서 업로드 키 재설정 요청, GitHub Secrets 교체
4. 사용자에게 영향이 있었다면 앱 설명·업데이트 노트로 알리고 수정 버전 배포

**앱 취약점 제보를 받았을 때**
1. 문의 이메일(kwangge95@gmail.com)로 접수, 받은 날짜 기록
2. 재현·영향 범위 확인 후 수정 버전 배포
3. 아래 변경 기록에 남김

**앱에 개인정보 처리 기능을 추가할 때** (서버, 로그인, 광고 SDK, 클라우드 동기화 등)
- 개인정보처리방침·데이터 보안 양식·이 문서를 함께 갱신하고, 유출 시 통지·신고 의무(「개인정보 보호법」)를 검토
